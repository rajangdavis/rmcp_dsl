# rmcp_dsl

A command line interface to compile a Ruby(ish) domain specific language into a working Model Context Protocol Server targetting the official Rust SDK.

`rmcp_dsl` reads a .rmcp.rb file, parses it with Prism, and emits a Rust crate that uses the [rmcp](https://crates.io/crates/rmcp)
SDK. Build the crate with cargo to get a server that speaks MCP over stdio.

`rmcp_dsl` also provides a language server for DSL files with the [`lsp` subcommand](docs/cli.md)
(`rmcp_dsl lsp`): diagnostics with quick fixes, hover types, go-to-definition, inlay hints and
completion, driven by the compiler on unsaved text. Editors that do not run an LSP client can
instead use `rmcp_dsl check FILE --format json --types`. See [Editor support](docs/editor-support.md).

Parts of code that need a Rust library (HTML parsing, URLs, DNS, case conversion) come in through typed bindings.

The tool bodies are ordinary-looking Ruby: strings, lists, integers, `if`, `case`, blocks, guard
clauses, helper functions.

Status: a working proof of concept, not a released tool. Tested with rmcp 3.5.0.

Built with Claude Sonnet 5.5 and Deepseek v4.1 Flash using the Claude Code and Opencode harnesses and the raj editor.

## Requirements

- Ruby 4.0.7 (see `.tool-versions`) with the `prism` gem (`bundle install`)
- Rust (rustc and cargo) for building rust code output
- Optional: `sorbet` (`srb tc`) for the structure check of the DSL files

## Quick start

```ruby
# examples/add.rmcp.rb
# typed: true
server "calculator", version: "0.1.0" do
  params :CalcParams do
    field :a, :i32
    field :b, :i32
  end

  tool :add, params: :CalcParams, description: "Add two integers" do
    body do |a, b|
      (a + b).to_s
    end
  end
  
  tool :subtract, params: :CalcParams, description: "Subtract two integers" do
    body do |a, b|
      (a - b).to_s
    end
  end

  transport :stdio
end
```

```sh
ruby exe/rmcp_dsl check examples/add.rmcp.rb      # validate only; writes nothing
ruby exe/rmcp_dsl build examples/add.rmcp.rb      # write build/add and run cargo build
ruby exe/rmcp_dsl run examples/add.rmcp.rb        # build, then serve MCP on stdio
ruby exe/rmcp_dsl init my_server                  # scaffold my_server.rmcp.rb and bindings/
```

The code compiles into the following Rust MCP Server code:

```rust
// Generated by rmcp_dsl from add.rb. Do not edit.
use rmcp::{handler::server::wrapper::Parameters, tool, tool_handler, tool_router, ServerHandler, ServiceExt};
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize, JsonSchema)]
struct CalcParams {
    a: i32,
    b: i32,
}

// overflow-checked integer arithmetic (only what this server uses): written by the compiler
fn arith_error(op: &str, a: impl std::fmt::Display, b: impl std::fmt::Display, b_is_zero: bool, ty: &str, min: i128, max: i128, at: &str) -> String {
    if b_is_zero && (op == "/" || op == "%") {
        format!("error: division by zero at {at}: {a} {op} 0. Fix: check that the divisor is not zero before dividing, or reject that input.")
    } else {
        let fix = if ty == "i64" {
            "i64 is already the widest integer type here, so limit the input range before this operation"
        } else {
            "declare the field as :i64 for a wider range, or limit the input range before this operation"
        };
        format!("error: integer overflow at {at}: {a} {op} {b} does not fit in {ty} ({min}..={max}). Fix: {fix}.")
    }
}

fn ck_add_i32(a: i32, b: i32, at: &str) -> Result<i32, String> {
    a.checked_add(b).ok_or_else(|| {
        arith_error("+", a, b, b == 0, "i32", i32::MIN as i128, i32::MAX as i128, at)
    })
}

fn ck_sub_i32(a: i32, b: i32, at: &str) -> Result<i32, String> {
    a.checked_sub(b).ok_or_else(|| {
        arith_error("-", a, b, b == 0, "i32", i32::MIN as i128, i32::MAX as i128, at)
    })
}

#[derive(Clone)]
struct Calculator;

#[tool_router]
impl Calculator {
    #[tool(description = "Add two integers")]
    fn add(&self, Parameters(CalcParams { a, b }): Parameters<CalcParams>) -> String {
        match (|| -> Result<String, String> {
            Ok(ck_add_i32(a, b, "examples/add.rb:10:8 in tool `add`")?.to_string())
        })() {
            Ok(s) => s,
            Err(e) => e,
        }
    }

    #[tool(description = "Subtract two integers")]
    fn subtract(&self, Parameters(CalcParams { a, b }): Parameters<CalcParams>) -> String {
        match (|| -> Result<String, String> {
            Ok(ck_sub_i32(a, b, "examples/add.rb:16:8 in tool `subtract`")?.to_string())
        })() {
            Ok(s) => s,
            Err(e) => e,
        }
    }
}

#[tool_handler(router = Self::tool_router(), name = "calculator", version = "0.1.0")]
impl ServerHandler for Calculator {}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let service = Calculator.serve(rmcp::transport::stdio()).await?;
    service.waiting().await?;
    Ok(())
}
```


While the rust code is not terrible, I have a strong preference for the ruby code.

My hypothesis with this libary is that having a middle layer between prompt and rust code output
can be beneficial.

## Install

As a gem: `gem build rmcp_dsl.gemspec`, then `gem install rmcp_dsl-0.1.0.gem`, then `rmcp_dsl --help`.
`make gem-test` proves `spec/shims/` shipped and that an installed gem finds a binding next to a file. `rmcp_dsl skill` writes an agent skill folder
(`rmcp-dsl/`) into the current directory, for any agent that reads `SKILL.md`.
